Proposed invariants

  • Draft changes never leak into published API responses.
  • Publishing is atomic: consumers see either vN or vN+1.
  • Rejection returns the revision to an editable draft.
  • Withdrawal and deletion are recoverable archival actions.
  • All changes, submissions, approvals, and API mutations are audited.
  • Authorization is enforced by organization, team, capability, and resource.

Role baseline

  • Event manager: creates and edits events within assigned teams; submits revisions.
  • Super user: works across the organization; reviews and approves revisions.
  • Administrator: manages organization settings, users, teams, event types, and credentials.
  • Proposed: the author of a revision cannot approve that same revision.

External API boundary

External applications may consume production data and change participation state without gaining authority over event definitions.

Allowed

Read approved event snapshots · sign up a participant · cancel a registration or individual occurrence · retrieve registration state

↔

Not allowed

Edit event definitions · bypass approval · hard-delete events · access another organization or team · read unpublished drafts

  2. Registration granularity

    Open

  3. Bookable sessions

    Are sessions schedule-only, individually selectable, or configurable per event type?

    Open

  5. Team ownership

  6. Participant identity

    Anonymous contacts, platform accounts, external identities, or a combination?

    Open

  7. Payments

    Open

  8. API visibility

    Public read endpoints for public events, scoped API credentials for all access, or both?

    Open

  9. Localization

    Do event content, schedules, and venues need multiple languages and time zones from the start?

    Open

Initial release sequence

Build one realistic vertical slice around a recurring event. Each phase introduces primitives that remain useful across future event types.

01 · Foundation

Identity & boundaries

Authentication, organizations, teams, roles, capabilities, authorization, and audit entries.

02 · Event core

Compose a recurring event

Event-type template, custom fields, series, occurrences, sessions, people, places, and fast list/search.

03 · Safe publication

Draft, review, publish

Revision editing, change summary, submission, approval, atomic snapshot publication, archive, and history.

04 · Distribution

API & participation

Scoped read API, registrations, per-occurrence cancellation, idempotent mutations, capacity, and API audit trail.
